## 1. プロダクトビジョン

URL入力という「最小操作」だけで、企業ごとのセキュリティ対策チェックシートを自動生成し、運用までを一気通貫で支援する。中小〜中堅企業のセキュリティ専門知識ギャップを埋める「最初の一歩」を提供する。

UIコンセプト: Hmhm (https://hmhm.wicle.io/) 風の URL入力中心の一画面起点UX。

## 2. 対象ユーザー (ペルソナ)

### Persona A: 田中 (情シス兼務 / 中堅製造業 200名規模)

- 役割: コーポレートIT + セキュリティ兼務担当
- 課題: 取引先からチェックシート提出を求められたが、何から始めればよいか不明
- ニーズ: 業界特化の最低限ガイドラインを短時間で網羅したい

### Persona B: 鈴木 (経営企画役員 / SaaS スタートアップ 30名規模)

- 役割: 経営層 + 情シス代行
- 課題: 病院への導入審査で医療系セキュリティ要件を求められた
- ニーズ: 医療ガイドラインのチェック項目を整理し、対応進捗を経営層に報告したい

### Persona C: 佐藤 (情報システム部長 / 自治体外郭団体 80名規模)

- 役割: 情報システム部長
- 課題: ISMS取得に向けた現状把握が必要
- ニーズ: 公的ガイドラインに沿った初期診断・ギャップ分析の素早い実施

## 3. ユーザーストーリー (機能要件)

### 3.1 分析・推定 (Epic: ANALYSIS)

| ID | ユーザーストーリー | 優先度 |
|----|------------------|--------|
| US-A01 | ユーザーとして、自社URLを入力するだけでサイト情報が抽出されることを期待する | P0 |
| US-A02 | ユーザーとして、抽出された情報からAIが業種・規模・取扱情報を推定し提示してほしい | P0 |
| US-A03 | ユーザーとして、推定結果に誤りがあった場合は手動で修正できる必要がある | P0 |
| US-A04 | ユーザーとして、推定の信頼度 (高/中/低) を視覚的に確認したい | P2 |
| US-A05 | ユーザーとして、過去に分析した同一URLは履歴から再開できると効率的である | P2 |

### 3.2 ガイドライン選定 (Epic: GUIDELINE)

| ID | ユーザーストーリー | 優先度 |
|----|------------------|--------|
| US-G01 | システムは推定属性に基づき、適用すべきガイドライン群を自動選定する | P0 |
| US-G02 | ユーザーとして、選定されたガイドライン一覧と選定理由を確認できる | P1 |
| US-G03 | ユーザーとして、自動選定に対しガイドラインを追加・除外できる | P1 |
| US-G04 | システムは横断ベースライン (IPA中小企業 / 経産省サイバーセキュリティ経営) を常時適用する | P0 |

### 3.3 チェックシート生成・管理 (Epic: CHECKLIST)

| ID | ユーザーストーリー | 優先度 |
|----|------------------|--------|
| US-C01 | システムは選定ガイドラインから対策項目を抽出・正規化しチェックシートを生成する | P0 |
| US-C02 | ユーザーとして、項目ごとに「未対応/対応中/完了/対象外」のステータス変更ができる | P0 |
| US-C03 | ユーザーとして、項目に担当者・期限・メモ・証跡URLを登録できる | P0 |
| US-C04 | ユーザーとして、優先度・カテゴリ・ステータスでフィルタリングしたい | P1 |
| US-C05 | ユーザーとして、進捗ダッシュボード (完了率・期限超過数) を一目で確認したい | P2 |

### 3.4 AIアシスタント (Epic: AI_CHAT)

| ID | ユーザーストーリー | 優先度 |
|----|------------------|--------|
| US-AI01 | ユーザーとして、項目詳細画面でAIに質問でき、項目コンテキストが自動付与される | P0 |
| US-AI02 | ユーザーとして、AI回答に「具体的な実装例」(例: AWS設定) が含まれてほしい | P1 |
| US-AI03 | ユーザーとして、AI回答にGood/Bad評価を付与しフィードバックできる | P2 |
| US-AI04 | システムはハルシネーション防止のため公的文書ソースへの誘導を含める | P0 |

### 3.5 エクスポート (Epic: EXPORT)

| ID | ユーザーストーリー | 優先度 |
|----|------------------|--------|
| US-E01 | ユーザーとして、現在のチェックシートをExcel形式でエクスポートできる | P0 |
| US-E02 | ユーザーとして、PDF形式でエクスポートし社内・取引先に共有できる | P0 |
| US-E03 | ユーザーとして、CSV形式でエクスポートしBI・社内DBに取り込める | P1 |
| US-E04 | ユーザーとして、エクスポート時にロゴ・社名を埋め込める | P3 |

### 3.6 認証・権限 (Epic: AUTH)

| ID | ユーザーストーリー | 優先度 |
|----|------------------|--------|
| US-AU01 | ユーザーとして、CC-Authでログインしテナント単位でデータが分離される | P0 |
| US-AU02 | Adminとして、Editor/Viewerを招待しロール割り当てができる | P1 |
| US-AU03 | Editorとして、ステータス・メモ更新は可能だがプロフィール削除は不可 | P0 |
| US-AU04 | Viewerとして、閲覧とエクスポートのみ実行可能 | P0 |

## 4. ユースケース (主要シナリオ)

### UC-1: 医療系SaaSスタートアップが病院導入審査向け対応

```
[Persona B: 鈴木]
1. トップ画面で自社URL (https://example-medical-saas.jp) を入力
2. システムがクローリング → 業種「ヘルスケアSaaS」「医療情報取扱」を推定
3. 「IPA中小企業」「経産省 経営」「NIST CSF 2.0」「厚労省 医療情報システム安全管理」が自動選定
4. ユーザーが推定属性「個人情報取扱: あり」を確認、シート生成確定
5. チェックシート画面で優先度P0項目から棚卸し
6. 不明項目「医療情報のアクセスログ要件」をAIに質問 → 具体的TODO策定
7. 対応完了項目の証跡URLを登録 (社内Wikiリンク)
8. PDF・Excelでエクスポート → 病院審査担当へ提出
```

### UC-2: 製造業 中堅企業の OT/IT セキュリティ初期診断

```
[Persona A: 田中]
1. 自社URL (https://example-manufacturing.co.jp) を入力
2. 業種「製造業」「BtoB」を推定
3. 「経産省 工場システム CPSF」「経産省 経営」が自動選定
4. OT領域 (制御系ネットワーク分離) の項目をAIに質問
5. AI回答 → 「IEC 62443 ゾーン分割」「DMZ構成例」を提示
6. 担当者を「OT管理課 山田さん」、期限を「2026-06-30」で登録
7. 月次でステータス更新、完了時にエクスポート → 親会社へ報告
```

### UC-3: 自治体外郭団体の ISMS 初期診断

```
[Persona C: 佐藤]
1. 自社URL入力 → 業種「自治体関連」「公共サービス」を推定
2. 「総務省 地方公共団体ガイドライン」「J-LIS ハンドブック」「IPA中小企業」が選定
3. ISMS関連項目 (アクセス制御 / 物理セキュリティ / 事業継続) を中心に棚卸し
4. ステータス「未対応」項目を担当者別にフィルタ → 対応計画を作成
5. PDFエクスポートで経営会議資料化
```

## 9. 受け入れ条件 (Acceptance Criteria)

PRD §16 に対応。すべての P0 機能実装後、以下を満たすこと。

- [ ] **AC-01**: 任意の有効な企業URL (200 OK返却) を入力した際、システムエラーを出さずに属性推定結果が返却される
- [ ] **AC-02**: 推定属性に基づき最低1つ以上の適切なガイドラインが自動選択される (横断ベースライン含む)
- [ ] **AC-03**: チェックシート上で各項目のステータス変更、テキストメモ保存、URL保存が正常に行える
- [ ] **AC-04**: AIチャットにおいて、対象チェック項目のコンテキストを踏まえた回答が生成される
- [ ] **AC-05**: チェックシートの内容が、レイアウト崩れなくExcelおよびPDFとしてエクスポートできる
- [ ] **AC-06**: ロール (Admin/Editor/Viewer) ごとの権限制御が機能する
- [ ] **AC-07**: CC-Auth ログイン後、テナント単位でデータが分離される
- [ ] **AC-08**: 推定結果の手動修正後、ガイドライン選定が再実行される

## 11. 制約・前提条件

- **重要**: 本ツールは公開情報+ユーザー入力に基づく**補助ツール**であり、法令適合性や認証取得の最終判断を代替するものではない。免責事項をUI上に明記すること
- LLM API利用時、ユーザーの非公開入力データは学習に利用させない契約 (オプトアウト) を採用
- プロンプトには企業ドメインと公開情報のみを利用し、ユーザー登録メモ・証跡URLはLLMに送信しない (またはマスキング)
- ガイドラインマスタは四半期更新。改版時のバージョン互換 (旧Assessmentは旧バージョンで保持) を保証
